- **Audit fixes (branch `fix/audit-m1-m4-findings`, run locally 2026-11-14, CI not yet run):**
  - **Egress guard (was High):** alternate IPv6 spellings of internal addresses (`::ffff:7f00:1`, `0:0:0:0:0:0:0:1`, `::ffff:a9fe:a9fe`) passed the guard, and the connector reached a loopback database with private networks disallowed. The guard now decides on the parsed address bytes: IPv6 is allow-listed to global unicast, IPv4-mapped and 6to4 addresses are judged by the IPv4 address inside them, and NAT64, Teredo, IPv4-compatible, scoped and unparseable addresses are refused.
  - **Access policy (D-16, Accepted 2026-11-14; formerly P-21):** `role_grants[].permissions` was unchecked, so a policy could grant any permission string. A policy can now grant only catalog permissions, never `tenant:manage`, `user:manage`, `data_source:manage`, `mapping:approve`, `semantic_model:manage` or `semantic_model:publish`, and not data grants written as permissions. The evaluator drops them from stored policies too. Row rules and column masks must name a column known for the entity (catalog columns, `id`, and columns the model names); a misspelt column used to be accepted and protected nothing.
  - **Semantic model:** column names (`attribute` of measures, filters and dimensions, and relationship keys) must be plain lower-case identifiers, in the Zod validator and the JSON Schema. They become SQL identifiers in the M6 compiler.
  - **Object approval:** approval now fails with 409 if the key selection changed while it was being checked.
  - Tests after the fixes: 146 api unit, 70 isolation (against a throwaway PostgreSQL), 6 ai-engine; ESLint, Prettier and the api type-check pass.

## Known issues and risks

  - The upload guard trusts the sizes an archive declares. Whether the parser bounds real expansion of a crafted archive is not verified.
  - The local key adapter (`LOCAL_KEK_BASE64`) is accepted with `NODE_ENV=production`; Compose runs that way. A managed KMS adapter is needed before any pilot.
  - The service token guard and the signed RequestContext are built and tested but protect no route yet, and the ai-engine has no authentication. Wire both with the first internal endpoint (M6).
  - Semantic model columns are checked for shape only, not for existence in the `analytics` tables (the template is checked by a test). Add the existence check with the compiler (M6).
  - The PostgreSQL connector was never run through the mapping flow, and its TLS verify modes are untested against a TLS server.
  - Denied requests are not audited. Data sources cannot be edited or deleted, so a credential cannot be rotated.
  - All six CI jobs passed on GitHub for the PR #5 merge commit on `main` (dd8c84c, checked 2026-11-14 through the public API). CI has not run on the audit fix branch.
